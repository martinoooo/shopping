# Ember & Oak · 面试演示脚本（约 5–6 分钟）

> 演示前：`npm install && npm run dev`，浏览器打开 `http://localhost:3000`，缩放到 100%。
> 手机端建议开 DevTools 的 iPhone 14（390 × 844）或直接投屏真机。
> 推荐先完整走一遍下单，让订单确认页保留在 localStorage（刷新也不会丢）。

## 0. 开场（20 秒）

「这是一个面向美国消费者的精品咖啡 DTC 独立站 **Ember & Oak**。我把它当作一个真实客户项目来做：
先确定品牌与商品结构，再围绕 **浏览 → 找到 → 理解 → 加购 → 结算** 这条主链路排优先级。数据是
mock 的，没有后端和真实支付，但所有状态、校验和价格计算都是真实可交互的。」

一句话说明取舍：
- **做深**：主链路、移动端、订阅、价格/运费/税费规则、演示细节。
- **不做**：登录、真实支付、后台、多币种——这些会稀释这次演示的重点。

## 1. 首页 · 品牌与发现（40 秒）

动作：缓慢滚动首页。

讲解点：
- Hero 用整幅摄影 + Fraunces 衬线标题，先建立品牌情绪，再给两个明确 CTA（Shop coffee / Our story）。
- 分类入口只有 3 个：Coffee / Brew gear / Cups & more——**减少选择成本**，符合咖啡品类的心智。
- Bestsellers + New arrivals 用统一的 ProductCard：悬停换图、收藏、快速加购，列表页就能完成转化。
- 「Find your brew」按冲煮方式反查商品，这是**用场景而非参数**帮用户做决定。
- 故事区给出可验证的数字（14 个合作农场 / 6 个国家 / 每周二烘焙），补足信任。

## 2. 浏览与筛选（60 秒）

动作：点导航 **Shop all** → 左侧筛选 Roast = Light、Brew method = Pour-over → 排序切换。

讲解点：
- 所有筛选条件同步到 URL（`?category=&roast=&method=&price=&sort=`），**可分享、可刷新、可回退**。
- 桌面侧栏、移动端底部抽屉，同一套筛选逻辑；已选条件以 chips 展示，可单独清除。
- 搜索：点右上角搜索，输入 `ethiopia` 或 `chocolate`，展示即时结果；空状态有引导。
- 真实电商里筛选不是装饰，它直接影响「找到想买的商品」的成功率。

## 3. 商品详情（70 秒）

动作：打开 **Ethiopia Guji Uraga**。

讲解点：
- 图片画廊 / 缩略图 / 移动端滑动；风味标签（Jasmine · White peach · Honey）与酸度/甜感/醇厚度可视化。
- 规格（250g / 500g / 1kg）与研磨度会实时影响价格——电商最常见的客诉之一就是规格与价格不透明。
- **订阅省钱**：切换 Subscribe & save，价格立刻 −15%，周期可选 2/4/8 周；这是复购模型的核心，不是附加功能。
- 库存与送达预期（周二烘焙、2–4 天送达）降低决策焦虑。
- 加入购物车 → 自动打开购物车抽屉 + toast 反馈，不打断浏览。

## 4. 购物车（35 秒）

讲解点：
- 免运费进度条（满 $60 免邮），差额实时计算，直接拉高客单价。
- 数量步进器、删除、编辑跳回商品页；订阅商品有明确 cadence 标签。
- 底部推荐搭配（来自 `pairsWith`），是提升 AOV 的低成本手段。
- 所有价格由 store 统一计算（小计 / 折扣 / 运费 / 预估税 / 合计），避免页面各处口径不一致。

## 5. 结算（60 秒）

动作：Checkout → 点 **Autofill demo details**（如无则手填）→ Continue → 支付页（测试卡）→ Review → Apply `WELCOME10` → Place order。

讲解点：
- 三步式进度（Shipping → Payment → Review），每步校验，支持返回修改。
- 顶部明确标注 **Demo mode — no real payment**，避免误解；一键填充让现场演示不卡壳。
- 右侧订单摘要 sticky，移动端可折叠；优惠码、运费、税费与购物车完全一致。
- 下单后在客户端生成订单号并跳转确认页；`lastOrder` 持久化，刷新不丢——演示更稳。

## 6. 订单确认（30 秒）

讲解点：
- 订单号、预计送达日期、商品明细、地址、金额拆分。
- 清空购物车、回到首页/继续购物，流程闭环。
- 刷新确认页仍然展示订单（localStorage），说明状态设计考虑了真实刷新场景。

## 7. 移动端（40 秒）

动作：切到 390px（或真机）。

讲解点：
- 移动端是海外 DTC 的主要流量来源：单列商品卡、全屏菜单、全宽购物车抽屉、底部吸附加购条。
- 触控目标 ≥ 44px；抽屉/弹窗锁定背景滚动、Esc 关闭、焦点陷阱。
- 没有横向滚动、没有遮挡，安全区（safe-area）留白。
- 图片全部本地 WebP，无外部图床依赖，弱网也能稳定演示。

## 8. 技术与收尾（60 秒）

- **栈**：React 19 + TypeScript + Vite + Tailwind + Zustand + React Router；无 UI 框架，设计系统自建。
- **状态**：购物车/心愿单/订单持久化；价格规则集中在 `store/cart.ts`，页面只消费。
- **性能**：本地 WebP、懒加载 + 骨架屏、代码按路由组织、字体自托管；首屏无外部请求。
- **可访问性**：语义化结构、键盘操作、焦点管理、reduced-motion。
- **部署**：`vercel.json` 已配置 SPA 重写与静态资源缓存，Git 导入即部署，无需环境变量。
- **下一步**：接 Shopify Storefront / Medusa 做商品与库存，Stripe 做真实支付，Algolia 做搜索，
  增加事件埋点与 A/B，补 Playwright 回归与 axe 可访问性检查。

## 演示边界（如被问到）

- 未做登录/账户体系：本次重点在游客转化链路，账户可后续叠加。
- 未接真实支付：已把支付步骤、校验、订单落库位置留好，接 Stripe 时替换 Payment 步骤即可。
- 商品与评价为 mock：结构按真实电商字段设计（SKU、规格、库存、烘焙度、风味、产地），便于对接后端。
